Business INTELLIGENCE & ANALYTICS DASHBOARD
=================================================

PROJECT PURPOSE
---------------
A Business Intelligence (BI) application that stores product information and
turns it into useful summaries. It helps a business/user compare product
categories, prices, ratings and review volumes through a dashboard and REST APIs.

IMPORTANT DATA NOTE
-------------------
The included CSV contains fictional demonstration records. It is not live Amazon
data and must not be presented as data collected from Amazon. For a real portfolio
demonstration, replace it with data you own, licensed data, an approved API, or
another source whose terms permit collection and use. Do not bypass website access
controls or scrape where prohibited.

TECH STACK
----------
- Python: main programming language
- Django: web framework and application structure
- Django REST Framework (DRF): product CRUD REST API
- PostgreSQL: primary production-style relational database
- SQLite: quick local fallback when DB_NAME is not configured
- Django ORM: database queries and aggregations
- Pandas: tabular data processing and price grouping
- NumPy: median calculation
- HTML/CSS/JavaScript: dashboard user interface
- CSV: simple bulk data import format

PROJECT WORKFLOW
----------------
1. DATA INPUT
   Product information enters through a CSV file. In a real deployment, the
   input could come from a permitted API, licensed dataset, or approved source.

2. VALIDATION AND CLEANING
   The import command checks required columns and converts price, rating and
   review count to suitable types. The model and serializer validate price and
   rating constraints. Missing ratings are stored as NULL.

3. DATABASE STORAGE
   Django models define the Product table. PostgreSQL is used when DB_NAME is
   configured. SQLite is available for a fast local demonstration.

4. API LAYER
   DRF ModelViewSet provides create, read, update and delete operations.
   Search, category/source filtering, ordering and pagination are enabled.

5. ANALYTICS
   Django ORM calculates count, average, minimum, maximum and category metrics.
   Pandas groups prices into ranges. NumPy calculates the median price.
   Rating distribution uses conditional Count and Q expressions.

6. DASHBOARD
   JavaScript fetches the API endpoints and displays KPI cards, product rows,
   category counts, price distribution and top-rated products.

DATABASE MODEL
--------------
Product fields:
- id: automatically generated primary key
- name: product name
- category: product category; indexed for common filtering
- price: decimal price (not float, to avoid common floating-point money issues)
- rating: optional decimal from 0 to 5
- review_count: non-negative whole number
- product_url: optional source/product URL
- source: data source label
- collected_at: timestamp when the row was created

MAIN ENDPOINTS
-------------
Dashboard:
  GET /

Product CRUD (DRF router):
  GET     /api/products/
  POST    /api/products/
  GET     /api/products/<id>/
  PUT     /api/products/<id>/
  PATCH   /api/products/<id>/
  DELETE  /api/products/<id>/

Query examples:
  /api/products/?search=mouse
  /api/products/?category=Electronics
  /api/products/?ordering=-price
  /api/products/?ordering=-rating
  /api/products/?page=2

Analytics:
  GET /api/analytics/summary/
  GET /api/analytics/categories/
  GET /api/analytics/top-rated/
  GET /api/analytics/price-distribution/
  GET /api/analytics/rating-distribution/

SUMMARY RESPONSE CONCEPTS
-------------------------
- total_products: number of stored products
- average_price: mean price
- minimum_price / maximum_price: lowest and highest prices
- average_rating: mean of available ratings (NULL ratings are ignored)
- median_price: middle price after sorting
- total_reviews: sum of review_count

CATEGORY ANALYSIS
-----------------
For each category, the endpoint returns product_count, average_price and
average_rating. This can help identify categories with higher average prices
or stronger ratings. A category with more products is not automatically more
profitable; sales and cost data would be needed to make that claim.

PRICE DISTRIBUTION
------------------
Pandas pd.cut assigns each price to one of these bands:
0-499, 500-999, 1000-1999, 2000-4999, 5000+.
The dashboard visualizes how many products fall in each band.

RATING DISTRIBUTION
-------------------
Conditional database counts group ratings into 0-1, 1-2, 2-3, 3-4, 4-5,
plus an Unrated group. The last rated bucket includes a rating of exactly 5.

SETUP ON WINDOWS
----------------
1. Extract the ZIP file.
2. Open the extracted folder in VS Code.
3. Open a terminal in this folder.
4. Create a virtual environment:
     py -m venv venv
5. Activate it in PowerShell:
     .\\venv\\Scripts\\Activate.ps1
   Or in Command Prompt:
     venv\\Scripts\\activate
6. Install dependencies:
     pip install -r requirements.txt
7. Copy .env.example to .env.
   For the fastest setup, leave DB_NAME unset. The project will use SQLite.
8. Create database tables:
     py manage.py makemigrations products
     py manage.py migrate
9. Import the included demo data:
     py manage.py import_products data/sample_products.csv
10. Start the server:
     py manage.py runserver
11. Open:
     http://127.0.0.1:8000/

POSTGRESQL SETUP
----------------
1. Create a PostgreSQL database, for example amazon_bi.
2. Copy .env.example to .env.
3. Set DB_NAME, DB_USER, DB_PASSWORD, DB_HOST and DB_PORT.
4. Ensure PostgreSQL is running.
5. Run migrations and import the CSV as above.
The settings automatically select PostgreSQL when DB_NAME is present.

INTERVIEW QUESTIONS AND ANSWER POINTS
-------------------------------------

1. What is Business Intelligence?
   BI is the process of converting raw data into meaningful information that
   supports business decisions. This project summarizes product prices,
   categories, ratings and review activity.

2. Explain the complete workflow.
   Data input -> validation/cleaning -> database storage -> API/query layer ->
   analytics -> dashboard -> interpretation of results.

3. Why did you choose Django?
   Django provides routing, ORM, models, admin, authentication foundations and
   a structured project framework, reducing the amount of boilerplate code.

4. What is Django REST Framework?
   DRF is a toolkit for building REST APIs in Django. It provides serializers,
   viewsets, routers, request parsing and response handling.

5. What is a serializer?
   A serializer converts model instances into representations such as JSON and
   validates incoming JSON before data is saved.

6. What is a ModelViewSet?
   It is a DRF class that provides standard CRUD actions using a queryset and
   serializer. A router maps those actions to API URLs.

7. What is CRUD?
   Create, Read, Update and Delete: the four basic operations for managing
   product records.

8. What is the Django ORM?
   ORM lets us work with database tables using Python model/query expressions
   instead of writing every SQL query manually.

9. Why use PostgreSQL?
   It is a robust relational database with transactions, indexing, constraints
   and strong SQL support. SQLite is used here only as a quick local fallback.

10. Why is price stored as DecimalField instead of FloatField?
    DecimalField is suitable for monetary values because decimal arithmetic
    avoids many binary floating-point representation surprises.

11. Why is rating nullable?
    Some products may not have a rating. NULL represents missing information
    more accurately than pretending the rating is zero.

12. What is the difference between NULL and zero?
    NULL means no value is available; zero is an actual numeric value.

13. What is aggregation?
    Aggregation calculates a summary across multiple rows, such as average
    price, minimum price, maximum price or product count.

14. What are Avg, Min, Max and Count?
    Django ORM aggregate functions that calculate average, minimum, maximum
    and number of matching records.

15. What is the purpose of Q objects?
    Q objects build complex query conditions and allow OR/AND combinations.
    Here they are used with conditional Count to calculate rating buckets.

16. Why use Pandas?
    Pandas provides DataFrame operations for tabular data, cleaning, grouping
    and categorization. This project uses it to create price ranges.

17. Why use NumPy?
    NumPy provides efficient numerical operations. Here np.median calculates
    the median product price.

18. What is median and how is it different from average?
    Median is the middle value after sorting. Average is the sum divided by
    count. Median is less affected by unusually high or low values.

19. What is price distribution?
    It shows the count of products in defined price intervals, helping users
    understand where most products are positioned.

20. What is rating distribution?
    It groups products by rating ranges, showing how ratings are spread across
    the catalogue.

21. What is pagination and why use it?
    Pagination returns a limited number of records per request instead of
    returning the entire table. It reduces response size and improves usability.

22. What are filtering, searching and ordering?
    Filtering narrows records by exact fields such as category. Search checks
    configured text fields. Ordering sorts results by fields such as price.

23. Why add a database index?
    An index can speed up lookups and filtering on frequently queried fields,
    at the cost of extra storage and slower writes. Category is indexed here.

24. What is an API?
    An API is an interface that allows one software component to communicate
    with another. The JavaScript dashboard calls the Django REST endpoints.

25. How does the frontend get analytics?
    JavaScript uses fetch() to call analytics endpoints, receives JSON and
    updates the dashboard elements.

26. How do you validate product data?
    The serializer and model validators check that price is not negative and
    rating is within 0 to 5. The import command also checks required CSV columns
    and converts values to appropriate types.

27. How would you handle duplicate products?
    Define a reliable unique business key (for example, a source product ID or
    normalized URL), add a database uniqueness constraint, and use
    update_or_create or bulk upsert logic. This starter does not yet implement
    deduplication.

28. How would you improve performance for a large dataset?
    Add suitable indexes, inspect query plans, avoid N+1 queries, cache expensive
    aggregates, use database-side aggregation, paginate, and consider background
    jobs for large imports.

29. What is the difference between average and weighted average rating?
    Simple average gives each product equal weight. Weighted average weights
    each rating by review count. This project currently uses simple average;
    a weighted metric could be added for a different business question.

30. What are the current limitations?
    The included data is a small demo dataset; no live Amazon integration,
    authentication/authorization, automated scheduled ingestion, deduplication,
    caching, or production deployment is included. These are possible next
    improvements, not features to claim as completed.

31. How would you test this project?
    Unit-test model validation and analytics calculations, API-test CRUD and
    filters, test CSV import edge cases, and perform an end-to-end dashboard
    check. A basic API test module is included.

32. What business insights can this dashboard provide?
    It can reveal category size, price bands, high-rated products and review
    volume. These are catalogue insights, not revenue/profit insights because
    sales, margin and inventory data are not included.

33. Why use an API between frontend and backend?
    It separates presentation from business/data logic and allows other clients
    to consume the same data.

34. What is REST?
    REST is an architectural style for networked applications. This project
    uses resource-oriented URLs and HTTP methods such as GET, POST, PATCH and
    DELETE.

35. What would you build next?
    Add authenticated users, source product identifiers, robust duplicate
    handling, scheduled permitted data ingestion, cached analytics, richer
    charts, export to CSV and deployment monitoring.
